Monetization & VIP

Admin-controlled pricing and monetization switches.

Activation and VIP are independent. Turning one off does not automatically turn the other on. Prices are configuration values; the actual payment/credit operation must also be enforced by the backend/database.

Referral System

Control referral rewards without hard-coding the amount.

Enable Referrals Allow users to invite other users.
Referral Reward Reward for a qualified referral.
Qualification Requirement Activation/VIP/task completion can be used as the trigger.
Maximum Referral Reward Per User 0 means no configured cap.

Anti-Abuse Rules

Referral rewards should not be released blindly.
Block Self Referral Reject matching/reflexive referral attempts.
Prevent Duplicate Reward One qualifying referral should not pay twice.

Security & Anti-Abuse

Controls for protecting task, proof, referral and financial workflows.

Account Protection

CAPTCHA Use CAPTCHA where your authentication/backend integration supports it.
Email Verification Require verified email where configured.
Block Duplicate Proof Flag repeated proof submissions.
Prevent Repeat Task Reward Respect max completions per user.

Financial Safety

Manual Withdrawal Review Do not automatically mark a withdrawal as paid.
Require Proof Review Reward only after proof reaches approved state.
Audit Financial Changes Record admin changes to platform settings.

High-Risk Operations

These should never be implemented as unrestricted client-side actions.
Never add a Supabase service-role key to this page. Balance adjustments, withdrawal payments, activation payments and privileged user operations should be protected with Supabase RLS or secure backend/Edge Functions.
